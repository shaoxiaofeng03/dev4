## 卡片清单（快速浏览 / 打印）

### 1. LLM 应用的四种形态是什么？各自的适用边界？

**答**：① Prompt 工程：改输入，成本最低，先做；② RAG：把外部知识检索进上下文，解决「不知道」和「知识过期」；③ Agent：让模型决定调用工具、分步执行，解决「步骤不定」；④ 微调：改变模型行为 / 风格 / 领域能力，成本最高，最后考虑。选型顺序通常是 Prompt → RAG → Agent → 微调。

<small>标签：全景 · ID：w1-c1</small>

### 2. 什么是 token？为什么它同时决定成本和延迟？

**答**：token 是模型处理文本的最小单位。API 按输入 + 输出 token 计费，上下文越长、输出越长越贵；输出 token 越多，推理耗时越长。所以「塞满上下文」既贵又慢。

<small>标签：基础 · ID：w1-c2</small>

### 3. 上下文窗口和最大输出长度是一回事吗？

**答**：不是。上下文窗口 = 输入 + 输出共享的总预算；最大输出长度是单次生成的上限。超窗口要做截断、摘要或检索，而不是硬塞。

<small>标签：基础 · ID：w1-c3</small>

### 4. temperature 和 top_p 分别控制什么？怎么选？

**答**：temperature 缩放概率分布：越低越确定、越高越发散；top_p 是核采样，只在累计概率前 p 的候选里采样。实践：抽取 / 分类 / 代码用 0–0.3；创意写作用 0.7–1.0；一般不要同时大改两个。

<small>标签：参数 · ID：w1-c4</small>

### 5. 为什么 LLM 调用必须加超时和重试？

**答**：模型 API 会超时、限流、返回 5xx，网络也会断。没有超时会把线程 / 请求挂死；没有重试会把偶发失败当成永久失败。做法：连接超时 + 总超时、指数退避 + 抖动、只对可重试错误重试、设置最大次数。

<small>标签：工程 · ID：w1-c5</small>

### 6. 结构化输出为什么需要「校验 + 重试」，而不是「让模型别出错」？

**答**：模型输出是概率生成，即使给了 schema 也不能保证 100% 合法。可靠做法是：定义 schema → 解析 → 校验 → 失败时带上错误信息重试 → 超过次数返回可读错误。这和生产系统校验外部输入是同一个思路。

<small>标签：结构化输出 · ID：w1-c6</small>

### 7. 一次 LLM 调用的成本怎么估算？

**答**：成本 ≈ 输入 token × 输入单价 + 输出 token × 输出单价。要先测平均输入 / 输出 token，再乘调用量。优化顺序通常是：减少无效上下文 → 缩短输出 → 缓存 → 换更便宜的模型。

<small>标签：成本 · ID：w1-c7</small>

### 8. RAG 和微调分别解决什么问题？什么时候选 RAG？

**答**：RAG 解决「模型不知道」和「知识过期」：把外部文档检索进上下文，更新快、可引用、成本低。微调解决「行为 / 风格 / 领域能力」：需要训练数据、成本高、更新慢。多数业务先从 RAG 开始。

<small>标签：RAG · ID：w1-c8</small>

### 9. Agent 和普通 LLM 调用最核心的区别是什么？

**答**：普通调用是「一次输入 → 一次输出」；Agent 让模型在多步循环里决定下一步动作、调用工具、观察结果，直到完成任务。代价是状态、错误恢复、评测和成本都更难。

<small>标签：Agent · ID：w1-c9</small>

### 10. 用 Java 后端的概念类比 LLM 客户端的三层防护。

**答**：超时 ≈ HTTP client 的 connect / read timeout；重试 ≈ Spring Retry / Resilience4j；结构化输出校验 ≈ DTO + Bean Validation。区别是 LLM 的输出不是可信输入，校验失败要带着错误信息重新请求，而不是直接抛给上层。

<small>标签：Java 类比 · ID：w1-c10</small>
