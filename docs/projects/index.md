# 作品集

三个项目对应「AI 应用开发 + Agent 平台 / 基础设施」双线。每个项目从立项就写清：解决什么问题、怎么评测、失败过什么、怎么启动。

## 项目总览

| 项目 | 周期 | 定位 | 状态 |
| --- | --- | --- | --- |
| 一、RAG 知识库 | W4–W6 | 应用线：文档接入、检索、引用、权限 | 未开始 |
| 二、Agent 工作流 + 运行时 | W7–W12 | 应用 + 平台线：工具、状态、恢复、trace、评测 | 未开始 |
| 三、Java 企业级 AI | W13–W14 | 差异化：Spring AI / LangChain4j、路由、审计、降级 | 未开始 |

## 项目一：RAG 知识库

**问题**：企业文档分散，搜索靠关键词，答案没有出处。

**要证明的能力**

- 可复现的 ingest 管道：解析 → 清洗 → 切分 → 向量化 → 入库。
- 检索策略有数据：BM25 / dense / hybrid / rerank 的 recall@k 对比。
- 答案带引用，能追溯到原文。
- 权限：不同角色只能检索自己的文档。
- 30 条评测集，优化前后对比。

**验收指标**

- [ ] 30 条评测集可一键跑。
- [ ] 至少 3 个 bad case，写清原因和修复。
- [ ] 一条命令启动服务。
- [ ] README 有架构图和失败排查。

## 项目二：Agent 工作流 + 运行时

**问题**：真实任务需要多步工具调用，失败要能恢复，过程要能审计。

**要证明的能力**

- 手写 ReAct 循环 → 再用 LangGraph 编排，知道框架在做什么。
- 工具注册表：统一 schema、错误格式、幂等性。
- 状态持久化：进程重启后能恢复。
- Trace / replay：能回放一次完整执行。
- 评测：30 条任务，成功率、步数、成本。
- Guardrails：危险工具、敏感信息、循环检测、人工审批。

**验收指标**

- [ ] 真实任务端到端跑通。
- [ ] 30 条评测有基线。
- [ ] 至少 5 个失败案例与修复。
- [ ] 3–5 分钟 demo，讲清架构取舍。

## 项目三：Java 企业级 AI

**问题**：企业存量系统是 Java，AI 能力不能只停在 Python demo。

**要证明的能力**

- Spring AI 或 LangChain4j 接入 RAG / Agent。
- 多模型路由与 fallback。
- 鉴权、审计、限流、成本上限。
- 与存量接口风格一致，有集成测试。

**验收指标**

- [ ] 主模型失败可降级。
- [ ] 审计日志可追溯：谁、何时、调了什么、花了多少。
- [ ] 权限可验证。
- [ ] 简历 v1 三个项目都有量化指标。

## 作品集叙事

面试时按这条线讲：

1. **应用**：我做过一个 RAG 知识库，解决什么问题，评测从多少提升到多少。
2. **平台**：为了让 Agent 跑稳，我做了工具注册、状态恢复、trace 和评测。
3. **差异化**：我把这些能力接进了 Java 企业系统，处理了权限、审计和降级。

> 每个项目至少准备两个「失败故事」：哪里判断错了、怎么发现、最后怎么修。
