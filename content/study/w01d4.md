## 讲义：卡住再查

### 结构化输出的三层

1. **提示层**：在 prompt 里给 schema、示例、字段说明。
2. **协议层**：使用 provider 提供的 JSON mode 或 function calling，让模型更容易产出合法结构。
3. **程序层**：解析 + 校验 + 重试 + 兜底。**这一层才是可靠性的来源。**

不要指望前两层 100% 正确；模型输出本质上仍是外部输入。

> Java 类比：prompt 里的 schema ≈ 接口文档；JSON mode ≈ 约定序列化格式；Pydantic ≈ DTO + Jackson；校验 ≈ Bean Validation；重试 ≈ 对不可信外部输入的保护。

### 一个够用的响应模型

本周你可以定义一个类似这样的结构：

```text
Answer:
  answer: str
  confidence: float (0-1)
  citations: list[str]
```

字段不要多。每多一个字段，就多一个模型出错的地方。先保证 `answer` 和 `confidence` 稳定，再扩展。

### 校验失败怎么重试

推荐流程：

1. 调模型 → 拿到文本。
2. 尝试 JSON 解析，失败则记录「解析错误」。
3. 用 Pydantic 校验，失败则记录「字段错误」。
4. 把错误信息追加到下一次请求里，例如「上次输出缺少 confidence 字段，请只返回 JSON」。
5. 超过最大次数，返回一个明确的错误类型，不把半成品交给上层。

重试次数不要无限；2 次通常够用。每次重试都要记录 tokens 和延迟，否则成本会悄悄翻倍。

### 失败测试怎么写

至少覆盖：

- 模型返回纯文本，不是 JSON。
- 模型返回 JSON，但缺少必填字段。
- 模型返回 JSON，但类型不对（例如 confidence 是字符串）。
- 模型超时 / 断网。

测试里不要真的调模型；把「模型返回」抽象成一个可替换的函数，用固定字符串模拟。这样测试稳定、快、免费。
