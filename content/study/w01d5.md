## 讲义：卡住再查

### 先固定评测集

本周不需要复杂的评测框架，5 组问题就够，但要满足：

1. 覆盖不同任务类型：事实问答、总结、改写、抽取、拒答。
2. 每组问题有「可判断好坏」的标准，而不是纯主观。
3. 每次都跑同一组，不要临时换题。

记录三列：输出摘要、tokens、延迟。质量用 1–5 分，写一句理由。

### 参数怎么影响输出

- **temperature**：越低越确定，越高越发散。抽取、分类、代码用 0–0.3；创意写作用 0.7–1.0。
- **top_p**：核采样。通常只调一个，不要同时大改。
- **max_tokens**：限制输出长度，也是成本上限。注意它不保证答案完整。
- **stop**：在特定标记处停止，适合结构化输出。

### 成本怎么算

成本 = 输入 token × 输入单价 + 输出 token × 输出单价。

要做三件事：

1. 用真实调用统计平均输入 / 输出 token，而不是拍脑袋。
2. 算「一次问答」和「一千次问答」的成本。
3. 找出最大的浪费：无效上下文、重复系统提示、过长输出。

> 优化顺序：删无效上下文 → 缩短输出 → 缓存 → 换更便宜的模型。不要一上来就换模型。

### Prompt 迭代记录

每次只改一个变量，记录：

- 改了什么（一句话）。
- 为什么改。
- 5 组问题的结果变化。
- 成本和延迟变化。
- 结论：保留还是回滚。

这张表会在 RAG 和 Agent 阶段继续用。
