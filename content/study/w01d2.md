## 讲义：卡住再查

### 推荐的目录

```text
projects/w1/
├── pyproject.toml
├── README.md
├── src/
│   └── w1/
│       ├── __init__.py
│       └── ...
└── tests/
    └── test_smoke.py
```

`src layout` 的好处是：测试和工具默认不会误导入项目根目录的临时文件，打包后也会把源码放进 `site-packages`，更接近真实安装后的行为。

> Java 类比：`src/w1` ≈ `src/main/java/com/example`；`tests/` ≈ `src/test/java`；`__init__.py` ≈ 包声明（现代 Python 里不强制，但保留更清晰）。

### pyproject.toml 管什么

- 项目元信息：名字、版本、Python 版本要求。
- 依赖：运行依赖和开发依赖。
- 工具配置：ruff、mypy、pytest 都可以写在这里。

`uv sync` 会根据 `pyproject.toml` 创建 `.venv`、解析依赖、生成 `uv.lock`。提交时提交 `pyproject.toml` 和 `uv.lock`，不要提交 `.venv`。

### 为什么现在就上 ruff / mypy / pytest

你后面要写的是「服务」，不是脚本。服务需要：

- 一致的格式（ruff），减少 review 噪音。
- 类型检查（mypy），在运行前发现 `None`、错参数这类错误。
- 自动化测试（pytest），证明失败路径真的被处理了。

现在配好，后面每个项目直接复用。

> Java 类比：ruff ≈ Spotless / Checkstyle；mypy ≈ 编译期类型检查；pytest ≈ JUnit。区别是 Python 的类型检查不阻止运行，所以更依赖 CI 和本地命令。
