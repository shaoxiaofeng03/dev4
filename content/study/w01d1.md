### AI 应用开发不是训练模型

你接下来要做的事，是把大模型当成一个「推理引擎」：它负责理解和生成，你负责给它上下文、给它工具、编排步骤，并对结果做校验和评测。

所以岗位叫「AI 应用开发」，不是「算法工程师」。前者拼的是工程能力：接口、检索、状态、评测、成本、权限；后者拼的是训练、数据、模型结构。

- **Prompt 工程**：改输入，成本最低，先做。
- **RAG**：把外部知识检索进上下文，解决「不知道」和「知识过期」。
- **Agent**：让模型决定调用工具、分步执行，解决「步骤不定」。
- **微调**：改变模型的行为、风格或领域能力，成本最高，最后考虑。

### 四层地图

今天画的地图不需要漂亮，但要能回答「每一层负责什么」：

1. **应用形态**：问答、知识库、Agent、工作流。

4. **模型与基础设施**：API、向量库、日志、成本、部署。

这张图会在 20 周里反复更新；今天只要知道每一层大概负责什么。

### 环境只要四样

Python 3.13 + uv + VS Code + Git。uv 同时管 Python 版本、虚拟环境和依赖，可以理解为「Maven + SDKMAN + venv」三合一。

每个项目一个 `.venv`，不要往系统 Python 里装业务依赖。先用 `uv --version`、`python --version` 验证，装库是后面的事。

> Java 类比：`pyproject.toml` ≈ `pom.xml`；`uv.lock` ≈ `pom.xml` 的锁定版本；`.venv` ≈ 项目私有的依赖目录；`ruff` ≈ Checkstyle / Spotless；`mypy` ≈ 编译期类型检查；`pytest` ≈ JUnit。
